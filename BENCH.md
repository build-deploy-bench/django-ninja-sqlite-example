# Build-deploy benchmark fixture: Django Ninja + SQLite

Private copy of [c4ffein/realworld-django-ninja](https://github.com/c4ffein/realworld-django-ninja) at
`87dd078c883a046f5ff20269df2fb004d8b5f83f` (2026-11-02), MIT license (kept in `LICENSE`). The first commit is
the unmodified upstream tree, including its three submodule gitlinks; each patch is a separate commit.

## Patches

- Removed the submodules (frontends, RealWorld spec), the root `Dockerfile`, `docker-compose.yml`, and the
  upstream CI workflows. A root `Dockerfile` changes build detection on Railway, Fly and Vercel.
- `gunicorn==26.2.0` added. `psycopg2==2.9.6` replaced by `psycopg2-binary==2.9.13`: `helpers/exceptions.py`
  still imports it, and the source package needs libpq headers and a compiler that differ per provider.
- `requirements.txt` is the lockfile (hashed, generated by uv; the regenerate command is in its header).
  Install uses `pip install --require-hashes`.
- `.python-version` = `3.12.16` (upstream ignored the file; now committed). Docker images use
  `python:3.12.16-slim-bookworm`.
- Settings: `DATABASE_URL=sqlite:////abs/path` selects file SQLite with `DEBUG` off (upstream allowed SQLite
  only with `DEBUG=True`). `SECRET_KEY` comes from the environment and is required when `DEBUG` is off.
  Production runs with `DEBUG` off.
- `GET /version` returns `{"commit": "<sha>", "run": "<id>"}`. `bench/build.sh` writes `.build-commit` from `BENCH_COMMIT`,
  `RENDER_GIT_COMMIT`, `RAILWAY_GIT_COMMIT_SHA`, `VERCEL_GIT_COMMIT_SHA`, then `git rev-parse HEAD`, else
  `unknown`. `run` is the runtime env var `BENCH_RUN_ID` (else `unknown`). The harness sets it before each deploy, so it identifies the deployment even when the commit is the same. The endpoint does not touch the database.
- `bench/build.sh {install|build|all}` with the `::bench::install_start/done` and `::bench::build_start/done`
  markers. Install = `pip install` of the lockfile (it creates `$VIRTUAL_ENV` first if it is missing, which
  Railpack needs). Python has no build the app needs; build = `python -m compileall` of the app sources plus
  writing `.build-commit`, so the build phase is short (well under 1 s).
- `bench/start.sh`: puts a repo-local `.venv` on `PATH` if one exists, defaults
  `DATABASE_URL=sqlite:////tmp/conduit.sqlite3` and `ALLOWED_HOSTS=*`, runs `manage.py migrate`, then
  `exec gunicorn config.wsgi --bind 0.0.0.0:$PORT` (1 sync worker). The database is empty on every new
  instance.
- `Dockerfile.fly` and `Dockerfile.vercel` (identical below the header), `fly.toml`, `vercel.json`.

## Commands

| | |
|---|---|
| Install | `./bench/build.sh install` |
| Build | `./bench/build.sh build` |
| Start | `./bench/start.sh` |
| Health path | `/api/tags` (200, `{"tags": []}`) |
| Commit check | `/version` |
| Env vars | `SECRET_KEY` (random, per provider). Nothing else is required. |
